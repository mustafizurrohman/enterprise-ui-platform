# Testing the datepicker

The datepicker is tested using Vitest and Angular `TestBed`. Consumer tests should focus on public behavior and accessible semantics.

## Testing Strategy

When querying elements, prioritize:
1. Accessible roles, native labels, and visible text.
2. Explicitly configured `testId` values.
3. Observable DOM state (ARIA attributes, disabled/checked states).
4. Bound form control values or `valueChange` outputs.

Note: The calendar is rendered in a CDK overlay. Query its content from the `document` rather than the fixture's native element.

## Test-ID contract

Use the `testId` input to provide a deterministic prefix for elements. If omitted, a random prefix is generated.

| Element | Test ID Pattern | Purpose |
| --- | --- | --- |
| **Input** | `[prefix]-input` | Manual entry field. |
| **Toggle** | `[prefix]-toggle` | Calendar open/close button. |
| **Clear** | `[prefix]-clear` | Clear button. |
| **Day** | `[prefix]-day-YYYY-MM-DD` | Specific date button in the grid. |
| **Time** | `[prefix]-[hour|minute|second]-input` | Spinbuttons for time units. |
| **Meridiem** | `[prefix]-meridiem-[am|pm]` | AM/PM radio inputs. |
| **Status** | `[prefix]-[input|dialog]-status` | ARIA status regions. |

## Key Testing Scenarios

- **Interaction**: Test opening via toggle or ArrowDown. Verify that Escape closes the dialog and restores focus.
- **Selection**: Assert that selecting a date updates the model without closing the dialog.
- **Validation**: Check for `invalidDate` errors on invalid manual entry.
- **Navigation**: Verify that arrow keys navigate the grid and skip filtered dates.
- **Normalization**: Test paste behavior and automatic separator insertion.

## Best Practices

- Use `fixture.detectChanges()` and `await fixture.whenStable()` to handle asynchronous overlay state.
- Avoid testing internal implementation details or private methods.
- Prefer semantic queries over internal CSS classes.
