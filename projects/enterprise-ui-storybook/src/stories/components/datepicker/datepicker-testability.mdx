# Testing the datepicker

The repository tests the datepicker with Vitest and Angular `TestBed`. Consumer tests should assert public behavior and accessible semantics rather than internal signals, private methods, generated Angular classes, or the component's internal DOM hierarchy.

Use queries in this order where practical:

1. accessible role, native label, and visible text;
2. an explicitly configured `testId` when the element has no suitable semantic query;
3. observable DOM state, including ARIA attributes and native disabled or checked state;
4. the bound form control or `valueChange` output.

The calendar is rendered through a CDK overlay. Query open dialog content from `document`, not only from `fixture.nativeElement`.

## Test setup

The following host exposes a deterministic test-ID prefix and uses a fixed reference date. Fixing `today` avoids assertions that depend on the machine clock.

```ts
import { Component } from '@angular/core';
import { ComponentFixture, TestBed } from '@angular/core/testing';
import { FormControl, ReactiveFormsModule, Validators } from '@angular/forms';
import {
  DatepickerComponent,
  DEFAULT_DATE_FORMAT,
} from '@mr/enterprise-ui/datepicker';
import { DateTime } from 'luxon';
import { beforeEach, describe, expect, it, vi } from 'vitest';

@Component({
  standalone: true,
  imports: [DatepickerComponent, ReactiveFormsModule],
  template: `
    <datepicker
      testId="booking-date"
      label="Booking date"
      [dateFilter]="dateFilter"
      [formControl]="control"
      [locale]="locale"
      [luxonDateFormat]="format"
      [showQuickTimeControls]="showQuickTimeControls"
      [today]="today"
    />
  `,
})
class DatepickerTestHostComponent {
  readonly control = new FormControl<Date | null>(null, {
    validators: [Validators.required],
  });
  readonly today = DateTime.fromISO('2026-07-20T00:00:00');
  readonly blockedDate = '2026-07-16';
  readonly dateFilter = (date: DateTime): boolean => date.toISODate() !== this.blockedDate;

  format = DEFAULT_DATE_FORMAT;
  locale = 'en-GB';
  showQuickTimeControls = false;
}

describe('DatepickerComponent', () => {
  let fixture: ComponentFixture<DatepickerTestHostComponent>;
  let host: DatepickerTestHostComponent;

  beforeEach(async () => {
    await TestBed.configureTestingModule({
      imports: [DatepickerTestHostComponent],
    }).compileComponents();

    fixture = TestBed.createComponent(DatepickerTestHostComponent);
    host = fixture.componentInstance;
    fixture.detectChanges();
    await fixture.whenStable();
  });

  // Tests shown below run in this suite.
});
```

Use small typed helpers for repeated DOM access. Throwing when an element is absent produces a clearer failure than an unchecked cast.

```ts
function elementFromFixture<T extends Element>(
  fixture: ComponentFixture<unknown>,
  selector: string,
): T {
  const element = fixture.nativeElement.querySelector(selector) as T | null;

  if (!element) {
    throw new Error(`Fixture element not found: ${selector}`);
  }

  return element;
}

function elementFromOverlay<T extends Element>(selector: string): T {
  const element = document.querySelector(selector) as T | null;

  if (!element) {
    throw new Error(`Overlay element not found: ${selector}`);
  }

  return element;
}

function dispatchKey(
  target: Element,
  key: string,
  options: Pick<KeyboardEventInit, 'altKey' | 'shiftKey'> = {},
): void {
  target.dispatchEvent(
    new KeyboardEvent('keydown', {
      bubbles: true,
      cancelable: true,
      key,
      ...options,
    }),
  );
}
```

## Opening and closing

Open the dialog through the public toggle or the input's documented keyboard behavior. Clicking the text input does not open the dialog.

```ts
it('opens the dialog from the toggle', async () => {

it('opens the dialog with ArrowDown', async () => {

```

Escape closes the overlay without modifying the value. Focus restoration is queued with `requestAnimationFrame`; stub it synchronously when the test must assert focus immediately.

```ts
it('closes with Escape without clearing the value and restores focus', async () => {
  const restoreAnimationFrame = vi
    .spyOn(window, 'requestAnimationFrame')
    .mockImplementation((callback: FrameRequestCallback): number => {
      callback(0);
      return 1;
    });

  const selected = new Date(2026, 6, 15);
  host.control.setValue(selected);
  fixture.detectChanges();

  const toggle = elementFromFixture<HTMLButtonElement>(
    fixture,
    '[data-testid="booking-date-toggle"]',
  );
  toggle.focus();
  toggle.click();
  fixture.detectChanges();
  await fixture.whenStable();

  const dialog = elementFromOverlay<HTMLElement>('[role="dialog"]');
  dispatchKey(dialog, 'Escape');
  fixture.detectChanges();

  expect(document.querySelector('[role="dialog"]')).toBeNull();
  expect(host.control.value).toEqual(selected);
  expect(document.activeElement).toBe(toggle);

  restoreAnimationFrame.mockRestore();
});
```

## Calendar keyboard navigation

Test keyboard behavior from the currently tabbable day button. After a navigation key, the new active day receives DOM focus and `tabindex="0"`.

```ts
it('moves calendar focus with the keyboard and selects with Enter', async () => {
```

## Manual entry and validation

Manual editing dispatches the native `input` event. Commit parsing with `blur` or Enter before asserting the final form state.

```ts
it('reports invalid manual input and associates the error', () => {
  const input = elementFromFixture<HTMLInputElement>(
    fixture,
    '[data-testid="booking-date-input"]',
  );

  input.value = '31.02.2026';
  input.dispatchEvent(new Event('input', { bubbles: true }));
  input.dispatchEvent(new FocusEvent('blur', { bubbles: true }));
  fixture.detectChanges();

  const error = elementFromFixture<HTMLElement>(
    fixture,
    '[data-testid="booking-date-error"]',
  );

  expect(host.control.hasError('invalidDate')).toBe(true);
  expect(input.getAttribute('aria-invalid')).toBe('true');
  expect(input.getAttribute('aria-errormessage')).toBe(error.id);
  expect(input.getAttribute('aria-describedby')?.split(' ')).toContain(error.id);
  expect(input.value).toBe('31.02.2026');
});
```

`Validators.required` is consumer configuration, not a built-in datepicker rule. Mark the control touched or dirty before asserting the visible Angular-control error state.

```ts
it('reflects a required form-control error', () => {
  host.control.setValue(null);
  host.control.markAsTouched();
  fixture.detectChanges();

  const input = elementFromFixture<HTMLInputElement>(
    fixture,
    '[data-testid="booking-date-input"]',
  );

  expect(host.control.hasError('required')).toBe(true);
  expect(input.getAttribute('aria-invalid')).toBe('true');
  expect(
    fixture.nativeElement.querySelector('[data-testid="booking-date-error"]'),

```

The built-in error text is format-oriented and does not identify whether the Angular control failed `required`, a range validator, or another custom validator. Tests that require rule-specific text should assert error content supplied by the surrounding application rather than expecting the component to generate it.

## Paste behavior

Construct a paste event with `clipboardData`, then assert the form value and the public status region. Avoid setting `input.value` directly when the behavior under test is paste normalization.

```ts
function dispatchPaste(input: HTMLInputElement, text: string): void {
  const event = new Event('paste', {
    bubbles: true,
    cancelable: true,
  }) as ClipboardEvent;

  Object.defineProperty(event, 'clipboardData', {
    value: {
      getData: (type: string): string =>
        type === 'text/plain' || type === 'text' ? text : '',
    },
  });

  input.dispatchEvent(event);
}

it('normalizes a pasted date', () => {
  const input = elementFromFixture<HTMLInputElement>(
    fixture,
    '[data-testid="booking-date-input"]',
  );

  dispatchPaste(input, '17/07/2026');
  fixture.detectChanges();

  expect(host.control.value).toEqual(new Date(2026, 6, 17));
  expect(
    elementFromFixture<HTMLElement>(
      fixture,
      '[data-testid="booking-date-input-status"]',
    ).textContent,
  ).toContain('Eingefügtes Datum übernommen');
});
```

## Test-ID contract

Set `testId` in component tests and end-to-end tests. When omitted or blank, the prefix is generated as `datepicker-<number>` and depends on component creation order.

Prefer semantic queries for labels, buttons, dialog, grid, spinbuttons, and radios. Use test IDs for exact dates, structural status regions, or controls whose fixed German accessible names would make locale-independent tests less clear.

| Element | Test ID or pattern | Purpose |
| --- | --- | --- |
| Component root | `&lt;prefix&gt;` | Root datepicker element. |
| Label | `&lt;prefix&gt;-label` | Native label associated with the input. |
| Input wrapper | `&lt;prefix&gt;-input-wrapper` | Input and action container. |
| Text input | `&lt;prefix&gt;-input` | Manual date/date-time entry. |
| Clear action | `&lt;prefix&gt;-clear` | Clears a non-empty enabled value. |
| Current date/time action | `&lt;prefix&gt;-now-input` | Applies the actual current date or time. |
| Input action icons | `&lt;prefix&gt;-clear-icon`, `&lt;prefix&gt;-now-icon`, `&lt;prefix&gt;-toggle-icon` | Material icon elements. Prefer the associated buttons. |
| Dialog toggle | `&lt;prefix&gt;-toggle` | Opens and closes the calendar. |
| Format hint | `&lt;prefix&gt;-hint` | Static input instructions referenced by `aria-describedby`. |
| Input status | `&lt;prefix&gt;-input-status` | Polite status region for paste, clear, and current-date/time actions. |
| Error | `&lt;prefix&gt;-error` | Rendered validation message. |
| Dialog | `&lt;prefix&gt;-dialog` | Modal overlay content. |
| Dialog title | `&lt;prefix&gt;-dialog-title` | Element referenced by `aria-labelledby`. |
| Dialog description | `&lt;prefix&gt;-dialog-description` | Static keyboard instructions referenced by `aria-describedby`. |

For date-independent matching, use a regular expression against the full value:

```ts
const dayTestIdPattern = /^booking-date-day-\d{4}-\d{2}-\d{2}$/;

const renderedDayButtons = Array.from(
  document.querySelectorAll<HTMLButtonElement>('[data-testid^="booking-date-day-"]'),
).filter((element) => dayTestIdPattern.test(element.dataset['testid'] ?? ''));
```

## Avoid brittle tests

Do not:

- call private datepicker methods or read private/internal signals;
- inject or mock implementation-only parser, ID, or accessibility services from consumer tests;
- query Angular-generated classes, CDK focus-anchor classes, or Material implementation classes;
- assume the overlay is a child of the fixture host;
- use arbitrary timeouts for overlay attachment, announcements, or focus restoration;
- infer selected state only from CSS classes when `aria-selected` and the form value are available;
- use generated fallback test-ID prefixes when a deterministic prefix can be supplied;
- assert undocumented internal element order.

Use `fixture.detectChanges()` after synchronous state changes and `await fixture.whenStable()` after opening or closing the overlay. Stub `requestAnimationFrame` only for behavior that is intentionally queued through it.
